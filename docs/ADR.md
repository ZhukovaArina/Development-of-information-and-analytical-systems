# Architecture Decision Records

## ADR-001: Yandex Cloud как облачный провайдер
**Статус:** Принято  
**Решение:** Использовать Yandex Cloud (Object Storage, Managed Kafka, Compute Cloud)  
**Причины:**
- Единая экосистема с API-совместимостью S3
- Управляемый Kafka без настройки инфраструктуры
- Российский регион с низкой задержкой

## ADR-002: Data Lake на S3 с Parquet
**Статус:** Принято  
**Решение:** Хранить данные в S3-совместимом Object Storage в формате Parquet  
**Причины:**
- Колоночное хранение = быстрые аналитические запросы
- Сжатие данных экономит до 80% места
- Совместимость с Spark/Pandas/ClickHouse

## ADR-003: Airflow для оркестрации
**Статус:** Принято  
**Решение:** Apache Airflow как ETL-оркестратор  
**Причины:**
- DAG как код (Python) для всех трансформаций
- Retry-политики и мониторинг из коробки
- Де-факто стандарт в индустрии

## ADR-004: Слои Bronze/Silver/Gold
**Статус:** Принято  
**Решение:** Три слоя данных: Raw → Bronze → Silver → Gold  
**Причины:**
- Bronze: сырые данные без изменений
- Silver: очищенные, дедуплицированные
- Gold: агрегаты и признаки для ML

## ADR-005: Kafka для real-time
**Статус:** Принято  
**Решение:** Managed Kafka + Python-сервисы для обработки событий  
**Причины:**
- Гарантированная доставка событий
- Потоковая агрегация в скользящие окна
- ClickHouse для хранения и аналитики

## ADR-006: Cube.js для семантического слоя
**Статус:** Принято  
**Решение:** Cube.js как семантический слой между данными и визуализацией  
**Причины:**
- Единые метрики и измерения для всех потребителей
- API-first подход для embedded-аналитики
- Поддержка ClickHouse из коробки
